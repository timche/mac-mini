# claude-hooks

`claude-hooks` is the binary every Claude Code hook on this Mac is a subcommand of, so that one build, one cache and one wrapper serve all of them. They are `guard` and `strip-attribution`, both `PreToolUse` on `Bash`; `project-docs`, which runs at `SessionStart`; and `herdr-worktree`, which runs at `PostToolUse` and `SessionEnd`.

`claude-hooks guard` is the `PreToolUse` hook on `Bash` in every Claude session on this Mac. It reads the command a session is about to run and refuses the two kinds that reach out of the session that ran them, each because many sessions share one machine:

- **A kill by name, pattern or port.** Each session runs its own copy of the same dev server in its own worktree, so a process named by its name, a pattern or the port it listens on is every session's copy of it: a `pkill -f portless` meant for one session's server stopped another's. A kill is allowed by pid alone, and a pid read off `pgrep`, `pidof`, `lsof`, `fuser`, `ps`, `netstat` or `ss` is a pid chosen by name or port all the same.
- **Taking the Mac's one foreground without the lock.** The GUI session has one frontmost app, one key window and one pointer, so `cliclick` and an `osascript` that sends a System Events keystroke, raises a window or clicks the screen reach whatever another session has in front. Those run under [`focus-lock`](../home/.local/bin/focus-lock), which serialises them, and this refuses them outside it. What reaches an app without the foreground — CDP, `perform action "AXPress"`, UTM's `input keystroke`, VNC — is left alone, which is why the check reads what a script does rather than refusing `osascript`. `$PROJECT_DOCS_DIR/shared/macos-gui-automation.md` says which call is which.

`claude-hooks strip-attribution` keeps Claude's attribution off GitHub, which git's own hooks cannot reach. A pull request, issue or comment body goes from `gh` straight to GitHub and never passes through `commit-msg`, and Claude Code's attribution setting only changes what the model is asked to write. So the attribution comes out of any `gh` command, and of any body file that command names — `--body-file`, `-F`, and on `gh api` a `--field key=@path` or an `--input` — before the command runs. Rewritten rather than refused, since a refused command is one an agent retries and works around.

What it does refuse is `--no-verify` on a commit or a push, and `-n` on a commit, which is the same flag there: both skip the `commit-msg` and `pre-push` hooks that keep the attribution off a commit, and the repository's own `pre-commit` with them. On a push `-n` is `--dry-run` and goes through. A permissions deny rule would not do this, since it matches only a command that starts with `git push`, which `git -C <dir> push` and a `cd … &&` chain are not.

Which command a word belongs to is read rather than matched, so `git commit -m "add a --no-verify guard"` is a message and not a flag, a `gh` in a heredoc body is a line of the file being written, and the only path written to is one a `gh` command named itself, resolved through a `VAR=…` the same line set and never through the environment.

It is a compiled binary rather than a script because a hook that cannot run is a hook that is silently off: a Python that a mise or a Homebrew upgrade moved takes the hook with it and nothing in a session says so. This depends on a kernel and nothing else.

## The commands

Each of the two `PreToolUse` hooks reads the hook event as JSON on stdin and prints a deny decision — `hookSpecificOutput`, `permissionDecision` `deny`, and the reason the refusing check gives — or nothing at all, which is how a command is allowed. `strip-attribution` has a third answer: an allow carrying `updatedInput`, the tool input back as it came with the command rewritten, which is what Claude Code then runs. Both exit 0 whatever they answer, and 1 when called wrong; never 2, which is how a `PreToolUse` hook blocks a command, so no bug here can cost a session its shell.

An event neither can read is allowed, and so is a command `guard` cannot read: `internal/shell` splits a command the way Bash would — quotes, `$()`, backticks, process substitutions, redirects, heredocs, `bash -c`, the prefixes that run another command such as `sudo`, `env`, `xargs` and `timeout` — and an unterminated quote, an unclosed substitution or a nesting deeper than anyone writes comes back as unreadable. A guard on every session's shell that refused what it could not parse would cost them all their shell. So a `pkill` in a commit message, a grep pattern or a heredoc body is an argument and goes through, and `internal/killbypid` and `internal/focus` decide only on a word a shell would run as a command.

`internal/attribution` reads the same command the same way, and falls back on a command it cannot read to matching the whole line as text: a skipped hook is refused and the attribution comes out of the command, but no file is touched, since a path read off a line nobody can split is not a path that command gave `gh`.

## The docs a session starts with

`claude-hooks project-docs` prints `~/projects/docs/shared` and the `~/projects/docs/<owner>/<repo>` folder that belongs to the project the session is in, each as a path followed by its top-level `*.md` files and its subdirectories as a name and a count. Stdout from a `SessionStart` hook is injected into the session context, so finding the docs is a mechanism rather than a rule the global CLAUDE.md asks a session to remember. It reads no event and answers nothing: whatever it could not read — a docs root that is not there, a directory the account cannot open, a git that will not answer — is a line the listing does not have, and it exits 0 either way.

Which folder belongs to the project is the `<owner>/<repo>` its `origin` remote names rather than the directory's name, since a worktree is named for its branch while every branch shares one docs folder; a repository with no remote falls back to the last two components of the directory its main worktree is in, a checkout sitting at `~/projects/<owner>/<repo>`. A checkout's own `docs/` is the project's published documentation rather than its working docs, so it is never looked at, and a project with no folder is not mentioned at all — otherwise every session on every other project would start with an apology.

`internal/collate` is why the order is what it was when this was a `find | sort` pipeline rather than Go's. `sort` in a session's locale compares case-folded, which puts `README.md` among the r's, and gives the punctuation a name is broken up with weights that are not ASCII's, which puts `mac-mini.md` before `mac.md`. Sorting by bytes instead would rewrite a listing in the context of every session for nothing.

## The worktree a session is working in

`claude-hooks herdr-worktree` gives a worktree Claude Code made for itself the place in herdr that a worktree herdr made has: a workspace of its own in the sidebar, named for the branch, with this session's tab in it, and the tab back in the workspace it came from once Claude leaves. Without it the session's own `EnterWorktree` is invisible — the tab stays in the workspace of the checkout while the work happens somewhere else.

It watches rather than takes part. Claude Code's `WorktreeCreate` hook replaces the creation it is a hook on, so wiring this there would move the making of the worktree — the base ref, the branch, what `ExitWorktree` cleans up — onto this side of the line, to be kept in step with a tool that already does it. So `EnterWorktree` and `ExitWorktree` create and remove exactly as they do without this, and what runs is a `PostToolUse` on the two of them and on `Bash`, and a `SessionEnd`. It reads the event, answers nothing, and exits 0 whatever happened.

Everything it does, it does through the pane the session is already in. `herdr worktree open` registers a worktree that exists rather than making one, and takes a shell tab of its own that nobody asked for, which is closed again. `herdr pane move` carries the pane, and so the terminal and the Claude process in it, into the new workspace. The pane id the session was started with keeps resolving to that pane wherever it has been moved to, which matters because it is the only id a process inside it has: `HERDR_PANE_ID` is set once, by the herdr that started the terminal. And a workspace whose last tab leaves is closed by herdr itself, so leaving a worktree is a move home and never a removal — the sidebar entry goes by itself.

The move takes the focus with it only when the pane was the one the eye was on, which is the pane's own focus and its workspace's together: a focused pane in a workspace nobody is looking at would otherwise pull the sidebar over to a worktree every time a session entered one.

Home at the end of the session as well as the end of the worktree, because whether Claude is keeping or removing the worktree is the answer to a prompt no hook sees, and the tab belongs where it came from either way. If that workspace has closed in the meantime the pane stays where it is: a workspace of its own would strand the tab somewhere belonging to no checkout, where leaving it in the worktree's is leaving it in one herdr closes when the pane finally goes.

The label follows the branch, since a session that renames or switches the branch under itself would otherwise leave the sidebar naming the one it entered on. That is what the `Bash` event is for, and it costs a session a state file and one `git` where there is a worktree and nothing at all where there is not.

Nothing here is worth a session's tool call: a terminal herdr did not start, a subagent, which works in the session's pane and has a directory of its own, a herdr that refuses, a payload that is not the shape it was — each is a return and a line on stderr.

## How it is wired

`home/.claude/settings.json` registers the two `PreToolUse` hooks once each for every Bash command, with no `if` filter, `project-docs` once for every `SessionStart`, and `herdr-worktree` twice: once for the three tools whose calls can move a session's worktree or its branch, and once for `SessionEnd`. A filter would be a second list of the programs a hook reads, kept in step by hand with the first, and Claude Code's matching sees through only its own fixed set of wrappers, so any runner missing from the filter would be a command that hook never saw. What `herdr-worktree` matches on is a tool name rather than anything about a command, which is why it can name the three it follows. The timeout is 30 seconds on a Bash hook, since a rebuild after an edit runs inside it, and 10 on the others, each with a session waiting on it.

What it registers is the built binary, `~/Library/Caches/claude-hooks/claude-hooks`, and the wrapper that builds it only when there is none: a shell, a `find`, a `shasum` and a `mise` before every Bash call in every session cost several times the check they are there for. So keeping an edit live is the binary's own job. The wrapper writes the folder it built from, and its own path, into the binary at build time; the binary, before it reads the event, compares the times of that folder's `*.go`, `go.mod` and `go.sum` and of the folders themselves — a deletion or a rename shows on the folder alone — against the newer of itself and `attempted`, and execs the wrapper with the event unread when the sources have moved. What answers the command is then a build of the sources as they are now. `CLAUDE_HOOKS_FRESH` says that handoff has happened, so there is only ever one.

## Setup, state and logs

Nothing to install: `mise.toml` links `home/.local/bin/claude-hooks` into `~/.local/bin`, and that wrapper builds the binary from this checkout's working tree into `~/Library/Caches/claude-hooks`, exactly as [hachiko's](../hachiko/README.md) does and for the same reasons. A wrapper run from a linked worktree builds into `~/Library/Caches/claude-hooks/worktrees/<name>` instead, since the hook runs the default cache's binary and that binary follows the sources it was built from. Sources whose times moved but whose contents did not are not rebuilt, and the wrapper touches `attempted` so the binary stops handing off. `go test ./...` is the gate between an edit and every session's shell, and a tree that does not build or does not pass leaves the last binary that did. The wrapper's one-line failures go to the session's stderr, which Claude Code reports as a hook error; there is no log file.

The state is the binary and `attempted`, which holds the hash of the sources at the last build attempt whether that attempt worked or not, and in its time when it was made. So a tree that does not compile is built once rather than before every command the session runs while it is fixing it, and the binary has something to measure the sources against. A cache with no binary in it is built from whatever `attempted` says, that being the one case where the hook reaches the wrapper at all.

`herdr-worktree` keeps a file of its own in `herdr-worktree/` beside the binary, one per session, holding the workspace its pane came from and the worktree and label it moved to, since nothing in a later event says any of that. It is deleted when the pane goes home; a session that was killed never gets there, so writing one sweeps the files a fortnight old.

`CLAUDE_HOOKS_CACHE_DIR` moves the cache, which is how a session tries a change without touching the one every other session is running.

## The tests are the specification

What the guard refuses is what `internal/killbypid` and `internal/focus` refuse in their tests, case by case, and what `strip-attribution` refuses, rewrites and leaves alone is the table in `internal/attribution`, each case a command a session really ran. What a session is told about its docs is the table in `internal/projectdocs`, a docs root and a repository per case, and the order those names come in is `internal/collate`'s, each of its cases an order `sort` itself produced. What `herdr-worktree` asks herdr for, and in what order, is the table in `internal/herdrworktree`: an event and a herdr that writes down what it was asked and answers from a file, over a checkout with a worktree where Claude Code puts one. `test/assert.sh` checks only that the binary is linked, that every hook the usage names is registered as the command above and for every event it answers, that each answers, and that an edit reaches a session: the handoff, a tree that does not compile, and a cache with no binary in it. A new way of killing by name, of taking the foreground or of sending a body to GitHub is a case in a table, not a line there.
